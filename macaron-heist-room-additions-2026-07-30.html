Addition 03 · Foundation

Give every generated interaction a visible action contract.

Macaron-style interfaces are powerful only if clicking them is predictable. The contract makes state, reads, execution, visibility, and proof explicit before the action runs.

Brings
A common safety model for buttons, forms, toggles, and future generated components.
Wins
No opaque onClick that quietly widens what the model can see or change.
thinkpool edge
Pair approval and room receipts make UI actions social and auditable.

Dependency: ship this contract before arbitrary generated actions.

Addition 05 · Foundation

Carry one canonical context contract through every handoff.

Today, every runtime and worker can receive its own dialect of the brief. A canonical envelope keeps the goal, authority, evidence, decisions, and return contract stable while adapters project only what each lane needs.

Brings
A single source of truth for conductor, worker, review, Design, and future runtimes.
Wins
Less handoff drift, fewer duplicated prompts, clearer receipts.
thinkpool edge
Runtime choice remains flexible without making context semantics provider-specific.

Boundary: project the minimum fields each lane needs; do not spray full transcripts.

Addition 06 · Later

Open the capability boundary after the trust model is proven.

Macaron hints at a broader agent ecosystem. thinkpool should expose the contracts—not the private guts—so external tools can join a route without owning the room, the context, or the approval model.

Brings
Adapters for goals, context, interactive UI, actions, proof, and reusable skills.
Wins
New capabilities can arrive faster without binding thinkpool to one model or one vendor.
thinkpool edge
The ecosystem plugs into thinkpool’s shared-room trust boundary instead of replacing it.

Sequence: earn this with additions 01–05 first. Distribution comes after coherence.
